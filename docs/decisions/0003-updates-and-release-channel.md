# 0003. Automatic updates and the release channel

- Status: accepted
- Date: 2026-11-26

## Context

From 0.2.0 Alchemide updates itself with the Tauri updater, which downloads `latest.json` from
`releases/latest/download/` on GitHub and installs only builds signed with the project's key.
The original plan published every `0.x` release as a pre-release, but GitHub never treats a
pre-release as the latest release, so the updater would never see a new version.

## Decision

- Releases are published as regular releases. They are still created as drafts, so the
  maintainer reviews and publishes each one.
- Updates are signed with a minisign key generated by `tauri signer generate`. The private key
  and its password live outside the repository and in the `TAURI_SIGNING_PRIVATE_KEY` and
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` secrets. The public key is in `tauri.conf.json`.
- Checking and installing run from Rust through the plugin's Rust API; the webview gets no
  updater permission.
- The check runs on start unless turned off in the settings, and "Check for updates" is in the
  command palette. This is the app's only network request, as stated in `TERMS.md`.

## Consequences

- `0.x` versions still carry no compatibility promise; that comes from semantic versioning,
  not from the pre-release flag.
- Losing the private key means installed copies can no longer update; a new key requires a
  manual reinstall.
- v0.1.0 has no updater, so users of it install 0.2.0 by hand once.
